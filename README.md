# Riverline

An English-only voice assistant for a realistic 30-day financial plan. This repository currently implements the authentication and workspace foundation, not the complete assignment.

Current scope: **local Docker Compose delivery and Track A conversational intelligence**. Hosted databases and cloud deployment are out of scope. See [conversation architecture](docs/conversation-architecture.md) for the proposed voice pipeline and conversation acceptance cases.

## Current capabilities

Email/password signup, login, persistent sessions, protected pages/API and signout work. Google OAuth is conditional on credentials and has not been verified with a live Google project. The responsive workspace uses shadcn/ui, ThinkingOrb and Motion, with income, commitments, essentials, plan sections and detail sheets. An authenticated tRPC query calls Python through a generated OpenAPI client.

Live Daily/Pipecat cascade audio is implemented: browser microphone → Daily → ElevenLabs streaming speech recognition → OpenRouter model → ElevenLabs streaming speech synthesis → Daily. The browser starts a private, expiring room through the authenticated backend. Financial editing/persistence, calculations and repayment plans are not yet implemented; financial fields remain explicitly empty. Voice usage incurs provider costs. Email verification and password recovery remain unimplemented.

## Docker startup

Requires Node 22+ for initial configuration and a running Docker engine with Linux containers.

```sh
npm run setup
docker compose up --build
```

Open **http://localhost:3000** and create an account with a password of at least 12 characters. Setup generates local secrets in ignored `.env`, preserving an existing file. Compose starts Postgres, Python and Next.js, applying authentication migrations before web startup. Accounts persist in the `postgres_data` volume.

`docker compose up --build` was verified on Ubuntu 24.04 through Docker Desktop's WSL integration on 2026-09-11. The final browser-to-bot conversation still requires an interactive microphone check.

## Local development without Docker

Requires Node 22+, Python 3.12 or 3.13, and [uv](https://docs.astral.sh/uv/). From the repository root:

```sh
npm ci
npm run setup
uv sync --project services/agent --frozen
```

Start the development database in one terminal:

```sh
npm run dev:db
```

This uses PGlite at `127.0.0.1:15432`, persisting synthetic data in ignored `.local/dev-postgres`. It is a development fallback, not the Compose database. Alternatively configure `DATABASE_URL` for native Postgres.

In a second terminal:

```sh
uv run --project services/agent --env-file .env uvicorn app.main:app --app-dir services/agent --host 127.0.0.1 --port 8000
```

In a third terminal:

```sh
npm run db:migrate
npm run dev
```

For a production web build locally, use `npm run build` then `npm start` instead. Start applies auth migrations automatically.

## Configuration

| Variable | Purpose | Required |
| --- | --- | --- |
| `APP_ORIGIN`, `BETTER_AUTH_URL` | Browser origin/auth base URL, locally http://localhost:3000 | Yes |
| `DATABASE_URL` | Database connection; Compose supplies internal host | Yes |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | Compose database settings; defaults are local-only | Compose |
| `BETTER_AUTH_SECRET` | Auth signing secret, generated by setup | Yes |
| `INTERNAL_API_SECRET` | Web-to-Python credential, minimum 32 characters, generated by setup | Yes |
| `AGENT_API_URL` | Python URL: localhost:8000 locally, agent:8000 in Compose | Yes |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Both enable Google OAuth | Optional |
| `DAILY_API_KEY` | Creates private, short-lived Daily rooms and participant tokens | Yes for voice |
| `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID` | Streaming speech recognition and speech synthesis | Yes for voice |
| `OPENROUTER_API_KEY`, `LLM_MODEL` | Streaming conversational model; default `openai/gpt-5.6-terra` | Yes for voice |
| `STT_MODEL`, `TTS_MODEL` | Streaming speech-model choices | Defaults provided |
| `VOICE_MAX_SESSIONS`, `VOICE_MAX_SECONDS` | Local concurrency and maximum call duration | Defaults provided |
| `SARVAM_API_KEY`, `OPENAI_API_KEY` | Reserved alternatives, not in current cascade | No |

For Google, create a Web application OAuth client in Google Cloud, configure its consent screen/test users, and register `http://localhost:3000/api/auth/callback/google` as an authorized redirect URI. Set both credentials in `.env` and restart. See [Google setup](https://better-auth.com/docs/authentication/google). Automatic account linking by matching email is disabled.

The selected cascade uses Daily, ElevenLabs and OpenRouter. The browser asks for microphone permission only after you press **Start live conversation**. The app does not retain audio recordings. The agent is English-only, does not calculate or save financial facts in this milestone, and describes those limits during the call. Sarvam and direct OpenAI Realtime remain alternatives rather than fallbacks.

## Verification

```sh
npm run lint
npm run build
npm run typecheck
npm test
uv run --project services/agent pytest services/agent/tests
uv run --project services/agent ruff check services/agent
docker compose config --quiet
```

With database and Python running and a built web app:

```sh
npx playwright install chromium
npm run test:e2e
```

Playwright starts the web server if needed. On Windows with installed Chrome, set `$env:PLAYWRIGHT_CHANNEL='chrome'` before running tests. Tests create synthetic accounts and screenshots under ignored `.Tmp`.

Regenerate contracts after changing Python API models:

```sh
uv run --project services/agent python services/agent/scripts/export_openapi.py
npm run contracts:generate
```

See [verification results and limitations](docs/verification.md).
